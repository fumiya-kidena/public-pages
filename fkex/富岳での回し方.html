富岳での回し方

最終更新：2026-07-12

FKeX（AMReX ベースの二相流ソルバ）を富岳（A64FX）で転送・ビルド・投入・後処理するまでの最短手順。設計判断や検証結果は開発ドキュメント・検証台帳を参照。ここは実行手順のみに絞る。

1. 設定の作り方

設定は AMReX ネイティブの ParmParse inputs ファイルが一次（そのまま使う）。手で書いてもよいが、ケース表 case/case.csv → python3 case/genInput.py <case> の1変換で生成する運用（FK3 の config.csv と同じ操作感）。ノブ名は機能プレフィクスで分類：vof.（VOF/サブグリッド）・tension.（表面張力）・amr.（AMReX格子）・bc.（境界条件）・fluid.・setup.・time.・proj.・diag.。

case.csv の bb3d（3D bag breakup）行の抜粋（列は機能プレフィクス付きヘッダ）：

amr.n_cell = 756 224 224
amr.max_grid_size = 14
bc.lo_x = inflow
bc.hi_x = outflow
bc.lo_y = slipwall / bc.hi_y = slipwall
bc.lo_z = slipwall / bc.hi_z = slipwall
bc.inflow_velocity = 21.796909486
bc.inflow_turb_intensity = 0.01
vof.n_subgrid = 2
vof.scheme = fgvt
tension.curvature = hf
tension.force = subgrid
tension.kappa_source = fine
setup.case = bagbreakup
chk.interval = 2000

生成：

python3 case/genInput.py bb3d

→ input/bb3d を書き出す（case.csv が正、input/* は生成物＝手編集しない）。

2. 回し方 4手

(1) ローカルでバンドル作成（自己完結 tar・AMReX 同梱、ネット不要でビルド可）：

bash job/makeFugakuBundle.sh

(2) 転送：

scp fkexFugakuBundle.tar.gz fugaku:~/
ssh fugaku 'tar xzf fkexFugakuBundle.tar.gz'

(3) ビルド（ログインノードで、FKeX ツリー直下から）：

cd ~/FKeX && bash job/buildFugaku.sh clang mpi

fkex2d.llvm.MPI.ex / fkex3d.llvm.MPI.ex が生成される（次元は入力ファイルの amr.n_cell の成分数から自動判定）。

(4) 投入（ケースごとの run ディレクトリで）：

cd run/bb3d && pjsub -x FKEX_CASE=bb3d -x FKEX_NP=<n> ../../job/fugakuRun.sh

pjsub の資源パラメタ（rscgrp・elapse・-g 等）は job/fugakuRun.sh 内に焼き込み済み（PJM ディレクティブ）。出力は log.dat 一本（rank 別ログではない）。ランク数 NP はケースの箱数（amr.n_cell/amr.max_grid_size の分割）を超えないこと（超えるとスクリプトが assert で止まる）。

後処理は：

python3 post/plot.py run/bb3d/

（各種 post/plot*.py はケース種別ごとに用意済み。README は post/README.md）

3. ポスト（可視化・定量）

3層で使い分ける：

  1. 時系列＝計算に組み込み済みの診断 CSV（log.dat、*_dropamp.csv 等）。富岳上でそのまま見られる、転送不要。
  2. 定量（破片サイズ分布・V(t)/A(t)/破断時刻）： 
    python3 post/src/bagBreakup/quant.py run/bb3d/
    plotfile（plt*）を直読みし、bb_fragment_pdf.png・bb_timeseries.png・bb_quant.csv を書く。解像度床 d_min = 4×dx_fine（最細レベルの4セル）未満の断片は本命の破片数からは除外（数値ノイズと区別するため）。
  3. 絵・動画：一度見るだけなら ParaView GUI で plt* を開き Contour フィルタ（vof=0.5）を当てるだけでよい（スクリプト不要）。連番アニメが要るときだけ post/src/bagBreakup/render_movie.py（pvbatch 専用、固定カメラ・固定色でPNG連番→ffmpeg結合）。

詳細は post/README.md（post/src/<case>/ 規約）とスクリプト冒頭コメント。

4. bb3d（3D bag breakup）設定要点

項目値
格子756×224×224（amr.max_grid_size=14 → 54×16×16=13,824 箱、各14³）
液滴密度・粘性ρl=1000 kg/m³、μl=1.0e-3 Pa·s
気相密度・粘性ρg=1.2 kg/m³、μg=1.8e-5 Pa·s
表面張力係数 σ7.08e-2 N/m（一様）
液滴径 D01.9 mm
Weber数15.3
曲率・表面張力ノブtension.curvature=hf（height function）、tension.force=subgrid、tension.kappa_source=fine（champion 経路）
境界条件x下=inflow（一様流入＋Klein乱流、§6）、x上=outflow、y/z=slipwall
想定並列本番：6912 rank＝144 node flat-MPI（48 rank/node）＝2 箱/rank。pilot（先行必須）：1152 rank＝24 node、FKEX_EXTRA=time.max_step=3000、elapse=03:00:00
想定 wall（本番）【暫定】約 21h（elapse=36:00:00 で投入）。pilot 実測で再校正すること
⚠ pilot を必ず先行させる：s/step 実測から本番 wall を確定し、inflow BC の MPI スケール健全性と SUBDIAG の sumcf_rel ドリフト率（全窓で <<1% が受け入れ基準）を確認する。本番は chk.interval=2000 でチェックポイントを刻むので、elapse 切れでも次節の手順でそのまま継続できる。メモリは ~12 MB/rank で余裕あり。

物性値の出所：旧ツリー FugakuTestRun_FK3_BagBreakup/Jakiw_We15_3_1per_Re2 のソース直書き（main.f90/initial.f90）から抽出（config.txt に物性キーはなし）。

5. restart（チェックポイント/再開）

ノブ chk.interval=<step間隔>（または sim 秒間隔の chk.time_interval）で、run ディレクトリ直下に chk<step>/ を書き出す（ネイティブ VisMF 保存＝外部依存なし、並列書き込み）。chk.keep=2（既定）でリングバッファ：常に最新2世代だけ残り、古い世代は書き込み完了後に削除される。

運用の要点：elapse が切れても、同じ run ディレクトリで再度 pjsub するだけで最新チェックポイントから自動継続する（chk.auto_restart 既定 on＝./chkLatest を見て再開、pjsub の行は変えない・追加フラグ不要）。目安は「elapse ≥ チェックポイント間隔（の実測 wall）に余裕を見た値」＝1 job で最低1回はチェックポイントを踏める設定にする。bb3d 本番の chk.interval=2000 は pilot 実測で間隔を再校正すること。

「連続走と再開走がバイト完全一致」を検証済み（2D・3D・乱流ON・8 rank すべてで、restart 後の全ログ・CSV・plotfile・checkpoint payload が完全一致）。

6. 乱流流入（Klein synthetic turbulence inlet）

bc.inflow_turb_intensity=0.01（流入速度の1% rms の Klein 合成乱流。既定 0=一様流入・摂動なし）。モード数は bc.inflow_turb_nmode（既定128）、乱数シードは bc.inflow_turb_seed（既定固定）で調整。bb3d は参照ケースに合わせ 0.01 に設定済み。
