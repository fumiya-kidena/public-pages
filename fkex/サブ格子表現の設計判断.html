サブ格子表現の設計判断 — AmrCore か、素の MultiFab か

2026-07-07 確定

FKeX のサブグリッド（界面用の全域 2 倍細分格子）を、AMReX の AMR 枠組み（AmrCore）に載せるか、素の MultiFab で自前管理するかの設計判断記録。AMReX を使う以上いちばん「らしい」道具は AMR だが、調べていくと FKeX の用途では前提そのものが噛み合わないことが分かった。その経緯を残す。全体像は開発ドキュメントを参照。

問いと結論

サブグリッドは「粗格子と同じ領域を 2 倍解像度で覆う細格子」で、一見 AMR の 2 レベル構成そのもの。AmrCore を継承すれば FillPatch・regrid・checkpoint などが「タダで」付いてくるように見える。それでも採らなかった。

結論：AmrCore には載せない。refine(BoxArray,2) ＋ 粗格子と同一の DistributionMapping を持つ素の MultiFab 2 組で自前管理する（ncomp パッキング案はランタイム表現としては却下、checkpoint 圧縮形式の将来オプションのみ温存）。

判断の芯：サブ格子 VOF は「一次状態」で、AMR の前提が反転する

AMR の根本前提は「粗レベルが全域で有効な真実。細レベルは粗から作り直せる使い捨てのビュー」。regrid も FillPatch（時間補間つき粗→細充填）も FluxRegister（粗細境界の保存補正）も、この前提の上の道具。

FKeX のサブグリッドはこれが逆：細格子の VOF が一次状態で、粗 VOF は平均（average_down）で得る導出量。真実の流れは細→粗の一方向で、粗→細は混合セル（VOF が 0 と 1 の間のセル）で一対多＝再構成不能。

つまり AMR の道具立ては、FKeX の静的全域細分では死荷重（regrid・proper nesting＝一度も使わない機構）か誤答（reflux＝前提が逆なので適用すると間違った補正になる）のどちらかになる。

効率とコード運用

前提の反転だけでなく、コスト・実装量の面でも素の MultiFab 管理が勝つ（あるいは負けない）ことを確認した。

観点要点
通信同一 DistributionMapping なら粗箱 i と細箱 i が常に同一 rank ＝ レベル間の valid 領域転送は全て rank 内局所（通信ゼロ）。細側カーネルから coarsen(i,2) で粗データを Array4 直接参照でき、汎用通信層（ParallelCopy/FillPatch）自体が不要。1 タイムステップに約 7 回ある密な粗⇄細往復でこれが効く。※AMReX の average_down が通信ゼロになるのも「BoxArray と DM が両方一致する時の高速パス」限定（不一致だと再分配コストのある汎用パスに分岐）
負荷分散静的全域細分では全箱が「粗+細」の同一コストなので、同一 DM の負荷ペナルティは厳密にゼロ（トレードオフ不存在）
実装量AmrCore 継承は派生クラスに 5 メソッドの実装義務（うち真の純粋仮想は ErrorEst と MakeNewLevelFromScratch の 2 つ）＝静的全域ではほぼ全部ダミー化する boilerplate 150–250 行。素の 2 レベル管理は struct 40–80 行。しかも AmrCore はサブグリッド結合の物理（速度補間・整合運動量集約・面力制限）を 1 行も肩代わりしない
「偽 friend」防御AMR には名前が似た別物 API がある — FluxRegister（粗細境界限定の reflux）は「全粗面での整合運動量フラックス集約」とは別物、average_down_faces（同一平面の横方向平均）は「法線方向の重み付き制限」とは別物、FillPatch の時間補間はそもそも不要。AmrCore を視界に置かないこと自体が、これらを"つい"使う事故の防御になる

必要な既製品（average_down / average_down_faces / FillPatchTwoLevels / FaceDivFree（対照実装用）/ WriteMultiLevelPlotfile / OverrideSync / VisMF）は全て AmrCore インスタンス無しで使えることをソースで裏取り済み。checkpoint の既製ヘルパーは AMReX 本体に無いので、VisMF 直叩きの自前実装がどの方式でも必要＝ここでは差がつかない。

前例

AMReX 公式の「Dual Grid」は particle-mesh の負荷分散専用で、同一物理場の二重解像度用途は文書化されていない。レベル間同一 DM を支援する公式パターンも無い（AMReX の標準思想は用途別 DM）。AMReX 上の dual-grid VOF の公開前例は見つからず＝この構成は明示的な設計判断として記録する価値がある。

将来：界面バンドだけの適応細分への道

現行の「全域細分」は、将来の「界面バンドのみ細分」の特殊ケース（バンド＝全域）。いま全域で楽をしても、後の載せ替えが高くつく書き方は避けたい。載せ替えを安くするための規律を最初から守る：

  1. 結合カーネルは「粗 Array4＋細 Array4＋Box」を取る自由関数にし、MFIter ループと分離（適応版はバンド上の MFIter から同一カーネルを呼ぶだけ）。
  2. 2 レベル管理を単一 struct に集約＝差し替え点を 1 ファイルに限定。
  3. plotfile・診断は最初から複数レベル形（Vector）で書く。
  4. 「混合セル＋ステンシルマージン ⊂ 細有効域」を不変条件として assert 可能に。バンドに新しく入るセルが純セル（VOF=0/1）なら細格子値の生成は情報損失ゼロ＝この性質がバンド適応化の成立条件。
  5. バンド縁ではカーネル論理自体が変わるため、マスク（iMultiFab）と縁の所有規約を集約カーネルと対で設計する。
  6. 適応版の負荷分散は「界面箱＝粗+細コスト、非界面箱＝粗のみ」の二重重みで粗 DM 自体を組み、細へ継承（結合局所性と負荷均衡の両取り）。この段階で初めて AmrCore の ErrorEst/タグ付け/クラスタリングが本物の利得になる。
