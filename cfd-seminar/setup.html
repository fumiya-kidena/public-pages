0. 環境構築

コードを書き始める前に、一度だけ済ませておく準備。次の順番で上から進める。

  1. エディタ Zed を入れる — この先ずっと使う作業場所
  2. GitHubアカウントと自分用リポジトリ（Fork）を用意する — ブラウザ
  3. Git for Windows を入れて、名前とメールを登録する
  4. Fork を C:\wrk\ にクローンする — Zed
  5. gfortran と make を入れて、PATH を通す — MSYS2
  6. Python と描画ライブラリを入れる
  7. Zed を再起動して、全部まとめて動作確認する
大原則: 何かをインストールしたり PATH を変えたりしたら、Zed をいったん完全に終了して開き直す。 Zed は起動した時点のPATHを覚え込むため、 開いたままだと新しく入れたコマンドが「認識されません」になる。この先の手順で何かが見つからないときは、 まず Zed の再起動を疑う（それでも駄目なら Windows からサインアウト→サインイン）。 ページ末尾につまずいたとき早見表もある。

1. エディタ: Zed

エディタを決めていない人は Zed を使う。動作が軽く、 ターミナルやGit操作までエディタ内に揃っているので、必要なものがほぼ1つで済む。 この先のクローン・コード編集・ビルド・実行・可視化・Git操作は、すべてこのZedの中で行う（ブラウザを使うのはForkのときだけ）。Windows 10以降で動く。

  1. zed.dev/download から入れる。
  2. 拡張機能パネルを開き（Ctrl+Shift+X）、「Fortran」で検索して Install。 これで .f90 が色分け表示される。

（任意）補完やエラー表示まで欲しい場合は、手順6でPythonを入れたあとに、Fortran用の 言語サーバ fortls を python -m pip install fortls で入れる（拡張が「Fortls not installed」と出すのはこれのこと）。

表示の設定（折り返し・パネル配置）

設定はsettings.jsonに書く。 Ctrl+, で開き、次の3行を { } の中に加える。 

{
  "soft_wrap": "editor_width",
  "project_panel": { "dock": "right" },
  "terminal": { "dock": "bottom" }
}

上から順に、長い行を画面幅で折り返す・フォルダ一覧を右・ターミナルを下（ここから make を打つ）に置く設定。

設定後のおおまかな画面配置。フォルダが右、ターミナルが下に来る。

2. 自分用のリポジトリを作る（Fork）

この演習は、配布元リポジトリ KIDENA-Fumiya/cfd-seminar を各自が Fork（フォーク）して、 自分のアカウントのコピーの上で進める。Forkだけはgithub.com（ブラウザ）上の操作。

  1. github.com で無料アカウントを作る。
  2. 配布元リポジトリのページを開き、右上の Fork ボタンを押す。
  3. Fork画面の Repository name を cfd-seminar-kidena のように末尾に自分の名前を付けて作成する（誰のForkか分かるように。kidena は例なので 各自の名前に置き換える）。
確認: 自分のアカウントの下に あなたのユーザー名/cfd-seminar-kidena のページが開ける。 以降はこの自分のForkだけを使う（配布元は触らない）。

3. Git for Windows と初回設定

クローンや履歴管理にはGit本体が必要。

  1. git-scm.com から Git for Windows を入れる （インストーラはすべて既定のまま「Next」で進めてよい）。
  2. 名前とメールを登録する（コミットに記録される情報。未設定だと最初のコミットで失敗する）。 Zedを開き直してから、下部ターミナルで一度だけ実行する: 
    git config --global user.name "あなたの名前"
git config --global user.email "you@example.com"
    メールはGitHubアカウントに登録したものにしておくとよい。
確認: ターミナルで git --version と打ってバージョンが表示される （「認識されません」ならZedを完全終了して開き直す）。

4. 自分のForkを C:\wrk\ にクローンする

Fork（GitHub上のコピー）を、自分のパソコンにクローンして編集できるようにする。Zedだけで完結する。

  1. コマンドパレット（Ctrl+Shift+P）で「clone」と打って git: clone を選ぶ （Zedのウェルカム画面の Clone a repository からでもよい）。
  2. 次のURLを貼る。<自分のユーザー名> は自分のGitHubアカウント名に置き換える: 
    https://github.com/<自分のユーザー名>/cfd-seminar-kidena.git
  3. 保存先を聞かれるので C:\wrk を選ぶ。C:\wrk\cfd-seminar-kidena\ に一式がコピーされ （C:\wrk フォルダは自動で作られる）、そのままZedで開く。

ターミナル派なら、Zedの下部ターミナルで git clone <上のURL> C:\wrk\cfd-seminar-kidena を実行し、 できたフォルダを Open Folder（メニュー）で開いても同じ。

URLは自分のForkのものを使う（配布元 KIDENA-Fumiya/cfd-seminar をクローンすると、あとで自分の変更をPushできない）。 迷ったら、ブラウザで自分のForkのページを開き、緑の Code ボタンからURLをコピーする。
確認: Zedの右パネルに src/・wrk/・docs/・post/ などのフォルダが見える。

変更をGitHubへ送る（Zed内で完結）

コードを直したら、ステータスバーのGitアイコンでGitパネルを開き、次を繰り返す。

  1. 変更したファイルにチェック（ステージ）→ メッセージを書いて Commit （コミット: 変更を履歴に記録）。
  2. Push（プッシュ: GitHubへ送る）。初回はGitHubログインを求められるので画面の指示に従う。

Forkだけはブラウザで行う操作で、それ以外（クローン・コミット・プッシュ・ブランチ）はすべてZedの中で完結する。 この先の各ステップでも、コードが動いて区切りがついたらそのつどコミット・プッシュしておくと、あとで前の状態に戻せる。

5. コンパイラ: gfortran と make（MSYS2）

Fortranのソースを実行できる形に翻訳するコンパイラ gfortranと、コンパイル手順をまとめて実行する make を、 MSYS2で入れる。

  1. msys2.org のインストーラを入れる（既定のまま。インストール先は C:\msys64）。
  2. スタートメニューから MSYS2 UCRT64（緑アイコンの専用ターミナル）を開く。 以降の pacman はこの窓の中でだけ使えるコマンド（Zedのターミナルや PowerShell では動かない）。
  3. 初回のみ、パッケージ情報を最新にする: 
    pacman -Syu
    途中で「ターミナルを閉じてください」と言われたら窓を閉じ、開き直して同じコマンドをもう一度実行する。
  4. gfortran と make を入れる（確認はそのまま Enter でよい）: 
    pacman -S mingw-w64-ucrt-x86_64-gcc-fortran make
確認: 同じMSYS2の窓で gfortran --version と make --version がバージョンを表示する。 （Zedのターミナルから使えるようにするのが次のPATH設定。）

PATH を通す

Zedの下部ターミナルから gfortran・make を呼べるよう、MSYS2の2つの bin フォルダを Windowsのユーザー環境変数 Path に追加する。 Zedの下部ターミナル（Windowsでは既定でPowerShellが開く）で次を一度だけ実行する（管理者権限は不要。1行で全部コピーする）: 

[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path","User") + ";C:\msys64\ucrt64\bin;C:\msys64\usr\bin", "User")
  • Zedのターミナルが PowerShell でない（プロンプトが PS> で始まらない）ときは、スタートメニューで「PowerShell」を検索して開き、同じコマンドを実行する。
  • GUIで入れるなら: 設定 →「環境変数を編集」→ 上段「ユーザー環境変数」の Path →「新規」で C:\msys64\ucrt64\bin と C:\msys64\usr\bin を1行ずつ追加しても同じ。
  • PowerShellでは $env:名前 でWindowsの環境変数を参照できる（例: $env:LOCALAPPDATA\Microsoft\WindowsApps。 ユーザー名を直書きせずパスを書ける）。
  • setx PATH "%PATH%;…" は既存PATH全体を複製・切り詰めて壊すことがあるので使わない。 Zedの settings.json でのPATH上書きも、Windowsでは既存PATHを引き継がないので使わない。

反映されたかの確認は、Zedを完全に終了して開き直したあとにできる（手順7でまとめて行う）。

6. Python（可視化用）

計算結果をグラフにする後処理（post/plot.py）にPythonを使う。

  1. Microsoft Store で「Python 3.13」を検索して入れる。これが一番簡単で確実 （PATHも自動で通り、インストール制限のあるPCでも入りやすい）。
  2. 描画ライブラリを入れる。ターミナル（Zed下部でよい）で: 
    python -m pip install numpy matplotlib
    pip 単体ではなく python -m pip で呼ぶのが確実（Store版は pip がPATHに無いことがある）。

Storeを使わない場合は、python.org のダウンロードページの 「Windows installer (64-bit)」（python-3.x.x-amd64.exe）でもよい。その場合は最初の画面で 「Add python.exe to PATH」に必ずチェックを入れる（これを忘れると python コマンドが見つからない）。

python.orgトップの大きなダウンロードボタンが配る「Python Install Manager」（Store形式のMSIXアプリ）は、 PCのポリシーで「サイドローディングはブロックされています」と弾かれることがある。その場合は上の Microsoft Store 版を使うのが確実。
確認: ターミナルで python --version と python -m pip --version がバージョンを表示する。

7. 動作確認（全部まとめて）

最後に、入れたものが全部Zedから使えることを確かめる。

  1. Zedを完全に終了して開き直す（PATHの変更を反映させるため。ウィンドウを閉じるだけでなく終了する）。
  2. C:\wrk\cfd-seminar-kidena を開き、下部ターミナルで4つともバージョンが出ることを確認: 
    git --version
gfortran --version
make --version
python --version
  3. お手本の src/ をビルド・実行する（コマンドは1行ずつ実行する）: 
    cd src
make
./cfd.exe
    画面に step= ... が流れ、1分ほどで Done. と出る。 リポジトリ直下の data/ に field_XXXXXX.dat が書き出されていれば成功。
  4. 結果を絵にする（リポジトリ直下に戻ってから）: 
    cd ..
python post/plot.py src/config.csv
    最新の計算結果を読んでグラフのウィンドウが開き、同じ場所に .png も保存される。
これで「コードを直す → make でコンパイル → 実行 → Pythonで可視化 → GitHubへ push」という 一往復がすべてできる状態になった。1. 導入 へ進む。

つまずいたとき早見表

症状原因対処
gfortran・make・python・git が「認識されません」 PATHが未設定、または変更前のPATHのままZedが起動している Zedを完全終了→再起動。直らなければPATH設定（手順5）を確認し、サインアウト→サインイン
pacman が「認識されません」 pacman はMSYS2の窓専用のコマンド スタートメニューから MSYS2 UCRT64 を開いて実行する
pacman -S が署名・鍵のエラーで失敗する パッケージ情報が古い pacman -Syu を実行してから入れ直す（窓を閉じるよう言われたら閉じて、開き直してもう一度）
python.orgのインストーラが「サイドローディングはブロックされています」 Store形式アプリ（Python Install Manager）がPCのポリシーで制限されている Microsoft Store版Python（手順6）を入れる
pip が「認識されません」 Store版Pythonは pip 単体がPATHに無いことがある python -m pip … の形で呼ぶ
python と打つとMicrosoft Storeが開いてしまう Python未導入時のWindowsの誘導機能 手順6でPythonを入れる（入れれば同じコマンドで本物が動く）
コミットが「Please tell me who you are」で失敗する 名前・メールが未登録 git config --global の2行（手順3）を実行する
Pushでログインを求められる 初回は正常な動作 画面の指示に従ってブラウザでGitHubにログインする
クローンが「repository not found」で失敗する URLが自分のForkになっていない、または打ち間違い ブラウザで自分のForkを開き、Code ボタンからURLをコピーし直す
make が「No targets specified and no makefile found」 src/ や wrk/ の外で実行している cd src（または cd wrk）してから make
&& を含むコマンドがエラーになる Windows PowerShell は && でコマンドをつなげない コマンドを1行ずつ実行する
Fortran拡張が「Fortls not installed」と出す 言語サーバ（任意機能）が未導入 Python導入後に python -m pip install fortls
